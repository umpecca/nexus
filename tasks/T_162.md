# T_162: Navigate Markdown links inside Nexus

Status: Complete

Open local Markdown links in the current Nexus editor using the link popover and Ctrl/Cmd-click. Resolve paths relative to the current document, including parent paths, encoded names, absolute paths, and file URLs. Support heading fragments and same-document anchors without reloading unsaved content. Preserve the opened folder, use normal Save/Discard/Cancel protection, and report missing or unsupported targets without replacing the buffer. Keep web/mail links in the default browser. Validate path resolution, trusted IPC, heading navigation, actual Electron link clicks, build, and lint; update product/architecture/changelog.

Implementation:
- Trusted link:resolve IPC resolves original Markdown URLs against the current document directory; HTTP(S)/mailto stay in the default browser. Local non-Markdown and unsupported scheme targets are rejected.
- Link popover Open and Ctrl/Cmd-click navigate through the normal document loader and dirty-buffer confirmation, retain the folder, reject stale reads, and report failures in a dialog.
- Modifier clicks read original Lexical link URLs because rendered hrefs rewrite bare paths to HTTPS and hide file URLs. Table/nested editor links use their owning editor.
- Same-document links preserve unsaved content. Decoded heading fragments share the TOC slugger and scroll after layout; heading extraction skips YAML frontmatter while preserving source line offsets.
- Product, architecture, changelog, and npm test:links updated.

Validation:
- 83 tests pass across link resolution, heading navigation, outline, TOC, and trusted renderer IPC.
- Real Electron smoke passes actual popover Open, Ctrl/Cmd-click, encoded/parent/file-URL links, heading fragments with YAML comments, folder retention, Save/Discard/Cancel, same-document unsaved content, missing/external links, and stale reads.
- Production build, lint, JavaScript syntax, and whitespace checks pass.
