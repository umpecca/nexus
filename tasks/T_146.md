# T_146: Require Local Owner Approval for MCP OAuth Connections

## Status

Done

## Summary

Prevent an HTTP client from approving its own OAuth connection and obtaining the MCP bearer token.
The browser requests connection approval; only a native Nexus dialog can grant it.

## Acceptance Criteria

1. Submitting the browser consent form cannot issue a code without explicit local approval.
2. The native dialog shows the client-reported name and callback address, with Deny as the default.
3. Missing approval support, dialog errors, rejection, replay, expired requests, and server/token
   changes fail closed. Concurrent requests cannot open multiple approval dialogs.
4. Approved connections retain PKCE validation and single-use authorization codes.
5. Regression tests, lint, TypeScript, Electron syntax checks, and production build pass.

## Implementation

- Kept the browser form as a request for approval and added a trusted main-process callback backed
  by a native dialog. Deny is the default and cancellation choice; client labels cannot add lines
  to the explanation. No renderer approval IPC or HTTP approval bypass was added.
- Consumed form requests before awaiting the owner, allowed only one pending dialog, and required
  a literal true response from the trusted callback. Missing callbacks and exceptions deny access.
- Invalidated authorization state on server configuration changes and token rotation; delayed or
  expired local decisions cannot issue codes. Existing PKCE and single-use code behavior is retained.
- Updated MCP settings help, product requirements, architecture, and changelog.
