# T_148: Preserve Edits During Asynchronous Saves

## Status

Done

## Summary

Fix review finding #3: saving must establish the saved snapshot as the baseline without replacing
edits made during the write. Save and Save As share a serial queue within each editor window.

## Acceptance Criteria

1. Edits made during Save or Save As remain in the editor and remain dirty until saved.
2. Overlapping saves execute in order and capture the latest buffer/path/baseline when they start.
3. A save for a replaced document cannot update the new document or redirect a queued save to it.
4. Failed/canceled saves do not mark the buffer clean; failures are visible and allow retry.
5. Save-before-close/open/new cannot discard edits made during the save.
6. Behavioral regression tests, lint, TypeScript, and production build pass.

Atomic disk writes and diagram cleanup ordering remain review finding #4.

## Implementation

- Added a shared per-window Save/Save As queue that captures text, destination, and prior baseline
  at execution time. Writes establish only the saved baseline, leaving the live editor untouched.
- Kept path and baseline refs current immediately after completion so queued saves use the
  preceding Save As destination and previous-version snapshots without awaiting React renders.
- Scoped saves to document identities; load/clear and asynchronous load completion invalidate
  obsolete completions, queued requests, and errors, including when reloading the same path.
- Added a save error dialog and explicit failure/cancellation returns. Save-before-close/open/new
  checks the live buffer after saving and preserves edits that arrived during the write.
- Added 15 delayed-promise hook tests and an Electron smoke test using the actual editor and preload,
  isolated in-memory browser storage, and synthetic save IPC. Wired the smoke into desktop CI.
