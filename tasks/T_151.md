# T_151: Detect External Edits Immediately After Save

## Status

Done

## Summary

Replace time-based file-watcher suppression with recognition of the exact content Nexus saved.
An external edit immediately after a save must still trigger the existing reload/conflict flow.

## Acceptance Criteria

1. A successful save produces no external-change event in the saving window for its own content.
2. Different external content, deletion, or replacement immediately after save is detected.
3. Failed and slow saves never absorb unrelated external edits into the watcher baseline.
4. Other windows watching the same document continue receiving the save as an external change.
5. Stale reads and watcher callbacks cannot affect a replacement document or closed window.
6. Filesystem regression tests, existing save tests, lint, and build pass.

## Implementation

- Extracted per-window watchers into `electron/documentWatch.cjs`. Directory watchers filter to the
  canonical document filename and survive atomic replacements, including symlink target writes.
- Replaced the 1.5-second suppression window and metadata signatures with SHA-256 content fingerprints.
  Successful saves acknowledge only their submitted bytes in the original saving watcher; failures
  leave its baseline unchanged. Pending saves defer checks until completion and trigger a disk recheck.
- Other windows keep their own baselines and receive the existing external-change notification.
  Generation and watcher-identity checks discard stale reads/callbacks after save, replacement, or close.
- Read acknowledgements use the exact Markdown returned to the renderer rather than another disk read.
  Watcher errors reattach readable files; deletion continues through the existing missing-file flow.
- Added 19 regressions using real files, controlled asynchronous reads, multiple windows, failed saves,
  same-size/same-mtime edits, immediate external edits, and native successive atomic replacements.
