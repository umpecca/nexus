# T_149: Atomic Document Saves and Post-Commit Diagram Cleanup

## Status

Done

## Summary

Fix review finding #4: replace Markdown and generated diagram files atomically, commit Save As
only after preparing its destination-specific contents, and remove obsolete diagrams after commit.

## Acceptance Criteria

1. Write, flush, or replacement failures leave the existing document and diagram assets intact.
2. Temporary files are created beside the destination and removed on handled failures; replacement
   never falls back to deleting or truncating the original. Existing permissions and symlinks work.
3. Save As selects a path before preparing assets and performs one final Markdown commit.
4. Cleanup follows a successful commit, preserves referenced assets and other in-flight assets,
   and cleanup failures do not turn a successful save into a reported failure.
5. Delayed/fault-injected filesystem tests, renderer save tests, lint, and build pass.

File-watcher suppression behavior remains review finding #5.

## Implementation

- Added exclusive sibling temporary writes, file flush/close, and rename replacement for Markdown
  and SVG sidecars. Failure never unlinks/truncates the destination. Symlinks resolve to their
  target, existing permission bits are retained, and handled failures remove temporary files.
- Replaced write-then-rewrite Save As with path-only selection and one final prepared commit.
- Moved diagram cleanup into the serialized main-process save transaction, after successful
  replacement. Removed the standalone renderer cleanup capability. Cleanup is best effort and
  removes only owned, previously referenced assets absent from the committed contents/keep list.
- Serialized commits by canonical path across windows and pinned staged SVGs by owner through
  commit, including old assets another window is reusing. Failed/preparation-only saves can leave
  extra sidecars; conservative retention protects other pending saves.
- Reattached document watchers to the replaced file identity and scheduled other windows' checks.
- Added filesystem tests with real files and injected partial-write, flush, close, rename, and cleanup
  failures, plus symlink, concurrency, reused staged asset, and renderer Save As regressions.

## Verification

- `npm run lint` — passed.
- `npm run build` — TypeScript and production build passed; existing Vite warnings remain.
- `node --check` for main, preload, atomic file, and document-save helpers — passed.
- `npm run test:document-save` — actual editor/preload smoke passed on Windows, including the new
  path-only Save As bridge, queued saves, retained live edits, close guard, and failure/retry.
- `npm run test:renderer-security` — passed on Windows. Both smoke tests also run in desktop CI.

Atomic replacement prevents partial files; this does not promise recovery from every power-loss
scenario or a transactional filesystem across multiple sidecars. Orphaned assets are retained safely.
